Detailed Description

Declares the setupRoutes function responsible for initializing and linking MVC components.

This header defines the setupRoutes() function, which connects views, controllers, and models through the Mediator pattern. It is called during application startup to initialize the GTK stack, controllers, and data models used across the app.

The function ensures that all UI views are properly bound, controllers are linked to their corresponding views, and models are registered in the Mediator for global accessibility.

Bootstraps the Application Architecture (MVC).

The setupRoutes function is the architectural "entry point" where the web of dependencies is spun. In this system, "routing" doesn't strictly mean URL routing (like in web apps), but rather the wiring of components.

Responsibilities:

  1. Instantiation: Creates instances of all Views, Controllers, and Models.
  2. Registration: Hands over ownership of these instances to the Mediator singleton.
  3. Dependency Injection: Connects controllers to their specific views.
  4. UI Initialization: Adds the view widgets to the main GtkStack, enabling navigation between them.

This function effectively transforms the application from a collection of classes into a running, interactive system.

stackPointer to the global GtkStack widget where all main views (Live, Playback, Settings) are added.

Bootstraps the Application Architecture (MVC).

This function is the primary bootstrap for the application. It proceeds in the following order:

  1. Initializes AI object detectors (e.g., YOLOv8) and moves them to the Mediator.
  2. Instantiates FunctionModel, FrameModel, and RegionModel, then attempts to load any existing database data.
  3. Instantiates all View classes (Live, Config, etc.).
  4. Instantiates all Controller classes.
  5. Registers all models, views, and controllers with the Mediator.
  6. Loads persistent user settings (like resolution) and sets the initial view to LiveView.
