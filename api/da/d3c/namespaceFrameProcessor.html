Detailed Description

Async Rendering Engine for Fisheye Transformations.

This namespace manages the parallel processing pipeline that converts raw camera frames into the various user-configured views (Panorama, Anypoint) for display.

Architecture:

  • Producer: The main loop captures a frame and spawns multiple FunctionProcess tasks.
  • Consumer: The ThreadPool executes these tasks, performing cv::remap and resizing.
  • UI Update: Completed frames are marshaled back to the Main Thread to update GTK widgets.

◆ processFramesAsynchronously()

void FrameProcessor::processFramesAsynchronously ( const FunctionProcess &  fp)

Worker: Executes a Single Rendering Task.

Processes a single frame asynchronously in a worker thread.

  1. Resolve: Determines if the view needs remapping (Panorama/Anypoint) or just resizing (Original).
  2. Transform: Calls remapFrame or resizeFrame accordingly.
  3. Analyze: (Optional) Checks zone policies for border alerts.
  4. Display: Uses g_idle_add to safely update the GtkImage on the main thread.
Parameters
fpThe job context.

Permanent optimizations included:

  1. Single-Pass Geometry (Consolidated stretch + fit)
  2. Pre-resolved Policy Guard (Zero search overhead in worker)
  3. Zero-Copy Move Semantics (Handover via pointer swap)

void FrameProcessor::processMultipleTasksAsync ( const std::vector< FunctionProcess > &  fps)

Dispatcher: Schedules Parallel Rendering Tasks.

Enqueues multiple frame processing tasks into the global thread pool.

Iterates through the list of FunctionProcess jobs and submits them to the ThreadPool. This ensures that multi-view layouts are rendered concurrently, utilizing all CPU cores.

Parameters

Core Transformation: Applies Optical Dewarping.

Applies a remapping transformation to a frame using pre-calculated maps.

Uses cv::remap with the pre-calculated LUTs (mapX, mapY) stored in the FunctionRecord. This is the most computationally expensive operation in the pipeline.
